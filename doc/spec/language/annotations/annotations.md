# Annotations

[← Index](../index.md) · [Classes](../structs/classes.md)

An **annotation** is a user-defined metadata type that can be attached to
aggregate declarations (classes, interfaces, structs, and other annotations).
At runtime, the annotation instances are accessible through the RTTI system
and can be inspected by user code.

## 1. Declaring an annotation type

An annotation type is declared with the `annotation` keyword, followed by a
name and a (possibly empty) body delimited by braces:

```k
annotation Deprecated {}

annotation Author {
    // Annotation types may not contain fields or methods in the current version.
}
```

### Rules

| Rule | Description |
|------|-------------|
| **Keyword** | `annotation` introduces the declaration. |
| **Body** | The body is currently empty — annotation types do not support fields, methods, or constructors. |
| **Implicit base** | Every annotation type implicitly inherits from `k::Annotation`, the root annotation class. |
| **Vtable** | Annotation types have a vtable with a single RTTI slot (slot 0), used for type identification at runtime. |
| **Default visibility** | Annotation types declared at namespace or module scope default to `public`. Visibility specifiers (`public`, `protected`, `private`) are supported when the annotation is nested. |

---

## 2. Applying annotations

An annotation is applied to an aggregate declaration by prefixing it with
`@AnnotationName`. The annotation definition appears **before** any specifiers
and the aggregate keyword.

```k
annotation Deprecated {}

@Deprecated
class OldService {
    public OldService() {}
    public dummy() : int { return 0; }
}
```

### Syntax

```
'@' QualifiedIdentifier [ '(' [ ExpressionList ] ')' | BraceInitList ]
```

Three initialization forms are supported:

| Form | Syntax | Example | Meaning |
|------|--------|---------|---------|
| **Default** | `@Name` | `@Deprecated` | Default-constructed annotation instance. |
| **Parenthesized** | `@Name(args…)` | `@Version(2)` | Constructor-style initialization (future use). |
| **Braced** | `@Name{…}` | `@Meta{.key="val"}` | Designated initialization (future use). |

> **Note:** In the current implementation, only the default form (`@Name`) is
> commonly used because annotation types have no user-defined fields or
> constructors. The parenthesized and braced forms are parsed but have no
> effect until annotation types support members.

### Applicable targets

Annotations can be applied to:

| Target | Supported |
|--------|-----------|
| `class` | ✓ |
| `interface` | ✓ |
| `struct` | ✓ |
| `annotation` | ✓ |
| Function | ✗ (future) |
| Variable | ✗ (future) |
| Parameter | ✗ (future) |

## 3. Multiple annotations

Multiple annotations can be applied to the same declaration. They are listed
sequentially, each preceded by `@`:

```k
annotation Alpha {}
annotation Beta {}

@Alpha @Beta
class MultiAnnotated {
    public MultiAnnotated() {}
    public dummy() : int { return 0; }
}
```

At runtime, `getAnnotations()` returns an array containing one `k::Annotation`
instance for each applied annotation, in declaration order.

## 4. Annotation inheritance from `k::Annotation`

Every annotation type implicitly inherits from `k::Annotation` (defined in
`libk/libk/src/rtti.k`). This base class provides:

| Method | Return type | Description |
|--------|-------------|-------------|
| `getAnnotationType()` | `const k::AnnotationType&` | Returns the RTTI descriptor for the concrete annotation type. |

The `getAnnotationType()` method is declared `final` — it cannot be
overridden. It reads the annotation's vtable slot 0 (the RTTI pointer)
to identify the concrete annotation type at runtime.

---

## 5. Annotation type RTTI — `k::AnnotationType`

Each annotation type has a corresponding `k::AnnotationType` instance
generated by the compiler. `AnnotationType` implements `k::AggregateType`
and provides:

| Method | Return type | Description |
|--------|-------------|-------------|
| `getName()` | `const char[]?` | Short (unqualified) name of the annotation type. |
| `getFullName()` | `const char[]?` | Fully qualified name (e.g. `"::mymodule::Deprecated"`). |
| `getBases()` | `const TypeInfo?[]?` | Base type descriptors (if any). |
| `getNested()` | `const TypeInfo?[]?` | Nested type descriptors (if any). |
| `getEnclosing()` | `const TypeInfo?` | Enclosing type descriptor, or `null` if top-level. |
| `getVisibility()` | `Visibility` | Declared visibility (`PUBLIC`, `PROTECTED`, `PRIVATE`). |
| `isStatic()` | `bool` | `true` if the annotation type is a static nested type. |

See [RTTI Types](../../stdlib/rtti.md) for the full stdlib RTTI type hierarchy.

## 6. Reading annotations at runtime

Annotations are accessed through the class or interface RTTI descriptor.
Both `k::Class` and `k::Interface` provide a `getAnnotations()` method:

```k
const getAnnotations() : const Annotation?[]?;
```

This returns `null` if the type has no annotations, or an array of
`k::Annotation?` pointers otherwise.

### Example — checking for an annotation by name

```k
import k;

annotation Marker {}

@Marker
class Target {
    public Target() {}
    public dummy() : int { return 0; }
}

test() : int {
    t : Target;
    anns : const k::Annotation?[]? = t.getClass().getAnnotations();
    if (anns == null) return 0;
    ann : const k::Annotation? = anns[0];
    if (ann == null) return 1;
    name : k::String(ann->getAnnotationType().getName());
    expected : k::String("Marker");
    if (name == expected) return 42;
    return 2;
}
```

### Example — polymorphic access to annotations

```k
import k;

annotation First {}
annotation Second {}

@First @Second
class Tagged {
    public Tagged() {}
    public dummy() : int { return 0; }
}

test() : int {
    t : Tagged;
    anns : const k::Annotation?[]? = t.getClass().getAnnotations();
    if (anns == null) return 0;
    // anns->size == 2
    // anns[0]->getAnnotationType().getName() == "First"
    // anns[1]->getAnnotationType().getName() == "Second"
    return anns->size;   // → 2
}
```

## 7. Annotation visibility and scope

### Scope

Annotation types follow the same scoping rules as other type declarations:

- They can be declared at module (top-level) scope.
- They can be declared inside a namespace.
- They can be nested inside a class, struct, interface, or another annotation.

When nested, the annotation type is accessible via the enclosing type's
qualified name: `Outer::MyAnnotation`.

### Visibility

Annotation types support the same visibility specifiers as other aggregates:

| Specifier | Meaning |
|-----------|---------|
| `public` | Accessible from any scope. |
| `protected` | Accessible from the enclosing type and its subclasses. |
| `private` | Accessible only within the enclosing type. |

Top-level annotation types default to `public`.

---

## 8. Restrictions

The following restrictions apply to annotation types in the current
implementation:

| Restriction | Description |
|-------------|-------------|
| **No fields** | Annotation types may not declare member variables. |
| **No methods** | Annotation types may not declare member functions (except the inherited `getAnnotationType()`). |
| **No constructors** | Annotation types may not declare explicit constructors. |
| **No destructors** | Annotation types may not declare destructors. |
| **No inheritance** | Annotation types may not extend other annotation types (future extension). |
| **Empty body** | The body must be empty `{}`. |
| **Target** | Annotations can only be applied to aggregate declarations (class, struct, interface, annotation). |

> **Future:** Fields, constructors, and annotation-to-annotation inheritance
> are planned but not yet implemented. When added, the parenthesized and
> braced initialization forms will be used to pass values to annotation
> fields at the declaration site.

## 9. Examples

### Marker annotation

```k
annotation Serializable {}

@Serializable
class Config {
    public Config() {}
    public load() : int { return 0; }
}
```

### Checking annotations at runtime

```k
import k;

annotation Deprecated {}

@Deprecated
class LegacyApi {
    public LegacyApi() {}
    public call() : int { return 1; }
}

is_deprecated(o : k::Object&) : bool {
    anns : const k::Annotation?[]? = o.getClass().getAnnotations();
    if (anns == null) return false;
    idx : int = 0;
    while (idx < anns->size) {
        ann : const k::Annotation? = anns[idx];
        if (ann != null) {
            name : k::String(ann->getAnnotationType().getName());
            target : k::String("Deprecated");
            if (name == target) return true;
        }
        idx = idx + 1;
    }
    return false;
}
```

### Annotation on an interface

```k
annotation Documented {}

@Documented
interface Describable {
    const describe() : int;
}
```

### Multiple annotations

```k
annotation Alpha {}
annotation Beta {}

@Alpha @Beta
class MultiTarget {
    public MultiTarget() {}
    public dummy() : int { return 0; }
}
```

## 10. Grammar

### Annotation type declaration

```
AnnotationDecl:
    { Specifier } 'annotation' Identifier '{' '}' 
```

Annotation types are parsed as a special case of `AggregateDecl` where the
aggregate keyword is `annotation`. They share the same specifier, base
clause, and body grammar, but the body must be empty in the current version.

### Annotation application

```
AnnotationDef:
    '@' QualifiedIdentifier
    | '@' QualifiedIdentifier '(' [ ExpressionList ] ')'
    | '@' QualifiedIdentifier BraceInitList

AnnotationDefList:
    { AnnotationDef }
```

Annotation applications appear before the aggregate declaration they
annotate:

```
AggregateDecl:
    { AnnotationDef } { Specifier } ( 'struct' | 'class' | 'interface' | 'annotation' )
    Identifier [ ':' BaseClause ] '{' { Declaration } '}'
```
